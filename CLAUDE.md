# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-host NixOS flake config for host `nixos` (Framework 13 AMD AI 300 series),
running Hyprland via Caelestia (`caelestia-shell`/`caelestia-dots`), managed with
home-manager. GNOME is kept installed as a fallback session.

## Layout

- `flake.nix` — inputs (`nixpkgs`, `home-manager`, `nixos-hardware`, `caelestia-shell`,
  `caelestia-dots`) and the `nixosConfigurations.nixos` output.
- `configuration.nix` — system-level config: bootloader, networking, GDM/GNOME,
  Hyprland enable, polkit, GNOME Keyring, audio, users, system packages.
- `home.nix` — user-level config for `senkoi`: Caelestia home-manager module,
  packages the upstream dotfiles expect, and the `hypr/` config pulled from
  `caelestia-dots`.
- `hardware-configuration.nix` — machine-specific, generated by the NixOS
  installer. Don't hand-edit; regenerate with `nixos-generate-config` if the
  hardware changes. Don't copy this file verbatim to a different machine.

## Rules

- Never run `sudo` or `nixos-rebuild switch` — the user applies rebuilds themselves.
- Validate changes with `nixos-rebuild build --flake .#nixos` instead.
- Never commit or push on your own. When a change is done and the build passes, stop and
  ask: "Ready to commit and push?" Only do it after the user says yes. The user will
  usually rebuild and test first.
- Wallpapers live in `~/Pictures/Wallpapers` and never go in git (not even the `wallpapers/`
  directory in this repo).
- Explain what a command does before running it — the user is learning.

## Commands

Rebuild and switch (applies system + home-manager config):

```fish
sudo nixos-rebuild switch --flake .#nixos
```

Build without switching (useful to check the config evaluates/builds before committing to it):

```fish
nixos-rebuild build --flake .#nixos
```

Check a flake/module evaluates without building derivations:

```fish
nix flake check
nix eval .#nixosConfigurations.nixos.config.<option.path>
```

Bump pinned flake inputs (`flake.lock`):

```fish
nix flake update
```

There is no test suite — correctness is checked by `nix flake check` / `nixos-rebuild build`
succeeding, and ultimately by switching and confirming Hyprland/Caelestia still start.

## Working on this repo

- This repo is normally checked out at `/etc/nixos`. Treat the repo root as that location
  when giving rebuild instructions.
- `hardware-configuration.nix` is machine-specific; never hand-edit it speculatively and
  never reuse one machine's copy on another.
- Prefer pulling upstream Caelestia files in declaratively (via `xdg.configFile.*.source`
  pointing at the `caelestia-dots` flake input) over hand-copying/retyping them, so they
  stay in sync with upstream.

## Caelestia-on-NixOS integration notes

Caelestia's upstream installer assumes a traditional, writable FHS-style dotfiles install.
Several things had to be special-cased to make it work under home-manager/Nix store
symlinks — see `README.md` for full detail, summarized here:

- **`~/.config/caelestia/` scaffold** (`home.activation.caelestiaConfigScaffold` in
  `home.nix`): `hyprland.lua` requires `hypr-vars`/`hypr-user` from this directory but
  only self-creates them if the directory already exists (`io.open` doesn't mkdir parents).
  The activation script creates the directory and three user-editable override files
  create-if-missing (never overwrite — these are meant to survive rebuilds after hand edits).
- **`xdg.configFile."hypr"` uses `recursive = true`, not a symlink**: `hyprland.lua` writes
  runtime state next to itself (copies `hypr/scheme/default.lua` → `current.lua` on first
  run, then `require`s it). A single read-only symlinked directory would break that write.
  `recursive = true` keeps the directory writable; only leaf files are store symlinks.
- **`programs.caelestia.systemd.enable = false`**: upstream `hypr/execs.lua` already
  autostarts `caelestia shell -d`; the home-manager module's own autostart would double-start it.
- **Polkit**: upstream `execs.lua` execs a hardcoded, non-NixOS polkit-gnome path that
  silently no-ops. Real agent is `services.hyprpolkitagent.enable = true` (home.nix) +
  `security.polkit.enable = true` (configuration.nix).
- **GNOME Keyring** is unlocked via GDM's password prompt regardless of which session
  (GNOME or Hyprland) is launched afterwards, so the PAM hook only needs to be wired onto
  `gdm`/`gdm-password` in `configuration.nix`, not per-session.

If something in Caelestia breaks after a `caelestia-dots`/`caelestia-shell` input bump,
check these integration points first — they're the parts upstream doesn't know is non-standard.
