# nixos-config

My NixOS flake: Hyprland + [Caelestia](https://github.com/caelestia-dots) via
`caelestia-shell`/`caelestia-dots`, managed with home-manager, on a Framework 13 AMD.

- NixOS 26.05
- Hyprland (Wayland compositor)
- Caelestia shell + dotfiles (hyprland.lua, fish, starship) pulled in declaratively
- home-manager for the user environment, system config for everything else
- GNOME kept installed as a fallback session (GDM lets you pick either)

## Layout

- `flake.nix` — inputs (`nixpkgs`, `home-manager`, `caelestia-shell`, `caelestia-dots`) and
  the `nixosConfigurations.nixos` output.
- `configuration.nix` — system-level config: bootloader, networking, GDM/GNOME,
  Hyprland enable, polkit, GNOME Keyring, audio, users.
- `home.nix` — user-level config for `senkoi`: Caelestia home-manager module,
  packages the upstream dotfiles expect, and the `hypr/` config pulled from
  `caelestia-dots`.
- `hardware-configuration.nix` — machine-specific, generated by the NixOS
  installer. Don't hand-edit; regenerate with `nixos-generate-config` if the
  hardware changes.

## Using this repo

On a fresh NixOS install:

```fish
sudo git clone https://github.com/<you>/nixos-config.git /etc/nixos
cd /etc/nixos
sudo nixos-rebuild switch --flake .#nixos
```

On this machine, after editing anything:

```fish
sudo nixos-rebuild switch --flake /etc/nixos#nixos
```

If `/etc/nixos` is a symlink/checkout of this repo already, just `cd` there and
run `git pull` first. `hardware-configuration.nix` is machine-specific — copy
the target machine's own copy over the one in this repo (or regenerate it)
before rebuilding on different hardware; don't reuse this one verbatim.

Flake inputs are pinned in `flake.lock`. Bump them with:

```fish
nix flake update
```

## Gotchas we hit getting Caelestia working on NixOS

Caelestia's upstream installer/config assumes a traditional dotfiles install
(files copied into `~/.config`, writable, with a Debian/Arch-style FHS). A
home-manager flake install is different in ways that broke things:

- **`hypr-vars`/`hypr-user` scaffold.** `hyprland.lua` does
  `require("hypr-vars")` / `require("hypr-user")` against
  `~/.config/caelestia/?.lua`, and only self-creates those files if
  `~/.config/caelestia/` already exists — `io.open(file, "w")` doesn't make
  parent directories. Since nothing else created that directory, Hyprland
  crashed on first login with `module 'hypr-vars' not found` before a single
  keybind was bound. Fixed with a `home.activation` script in `home.nix` that
  scaffolds `~/.config/caelestia/{hypr-vars.lua,hypr-user.lua,user-config.fish}`
  if missing — these are meant to be user-editable overrides, so it's
  create-if-missing, not overwrite.

- **Writable `hypr/` directory.** `xdg.configFile."hypr"` pulls in the
  upstream `hypr/` directory (hyprland.lua + `hyprland/*.lua`) from
  `caelestia-dots`. It uses `recursive = true` instead of a single symlink,
  because `hyprland.lua` writes runtime state next to itself — it copies
  `hypr/scheme/default.lua` → `hypr/scheme/current.lua` on first run, and
  `misc.lua` does `require("scheme.current")` at config load. A single
  read-only symlinked directory would make that copy fail and hard-crash
  Hyprland startup. `recursive = true` keeps the directory itself real and
  writable; only the leaf files underneath are symlinks into the Nix store.

- **Disabled double autostart.** Upstream `hypr/execs.lua` already launches
  `caelestia shell -d` when Hyprland starts. `caelestia-shell`'s
  home-manager module also offers its own systemd autostart for the shell —
  enabling both starts it twice. `programs.caelestia.systemd.enable = false`
  in `home.nix` disables the module's own autostart and leaves Hyprland's
  `execs.lua` as the single source of truth.

- **Polkit agent.** Upstream `execs.lua` tries to exec a hardcoded
  `/usr/lib/polkit-gnome/...` path for the polkit authentication agent, which
  doesn't exist on NixOS — that line silently no-ops, so you'd never get an
  auth prompt. Replaced with the real, Hyprland-native equivalent:
  `services.hyprpolkitagent.enable = true` in `home.nix`, plus
  `security.polkit.enable = true` in `configuration.nix`.

Also wired up GNOME Keyring (`services.gnome.gnome-keyring.enable` +
`security.pam.services.gdm{,-password}.enableGnomeKeyring` in
`configuration.nix`) since GDM's own password prompt is what unlocks it,
regardless of whether you then launch the GNOME or Hyprland session.
